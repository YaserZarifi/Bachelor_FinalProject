## ۶. مهم‌ترین سناریوهای پوشش‌داده‌شده

### ۶.۱ مدل دسترسی دوگانه (ثبت ناشناس)

```
شهروند ناشناس → POST /api/reports/ → ۲۰۱ + guest_access_token
                                    ↓
        GET /api/reports/{id}/?guest_token=…      → ۲۰۰ ✅
        GET /api/reports/{id}/  (بدون توکن)       → ۴۰۴ ✅
        GET /api/reports/{id}/?guest_token=غلط    → ۴۰۱ ✅
        توکن گزارش A روی گزارش B                  → رد ✅
        ws/reports/{id}/?guest_token=…            → پذیرش ✅
```

### ۶.۲ ماشین حالت گزارش

هر شش وضعیت و همهٔ گذارهای مجاز و غیرمجاز آزموده شده‌اند؛ از جمله:

* `SUBMITTED → RESOLVED` (پرش غیرمجاز) → رد می‌شود ✅
* رسیدن به `RESOLVED` بدون «تصویر بعد» → رد می‌شود ✅
* `CLOSED` پایانی است و هیچ گذاری از آن مجاز نیست ✅
* پیمایش کامل چرخهٔ عمر از ابتدا تا انتها → موفق ✅

### ۶.۳ ضد‌تقلب (ثبت مطمئن)

* دقت GPS بزرگ‌تر از ۲۰۰ متر (نشانهٔ VPN/IP) → رد در سرور *و* در کلاینت ✅
* ثبت با دوربین بدون اعلام دقت GPS → رد ✅
* ویرایش کارمند نمی‌تواند `capture_source`، `captured_at`، `gps_accuracy` یا
  `client_integrity_hash` را بازنویسی کند ✅
* تغییر یک بایت از عکس، مختصات یا زمان → اثر انگشت تغییر می‌کند ✅

### ۶.۴ تاب‌آوری در برابر خرابی سرویس‌های بیرونی

| سرویس خراب | رفتار تضمین‌شده |
|-------------|------------------|
| Redis / لایهٔ کانال | ثبت گزارش شهروند همچنان موفق است |
| کارگزار Celery | ثبت گزارش و تغییر وضعیت همچنان موفق است |
| Groq (مدل زبانی) | دسته «نامشخص» می‌شود؛ گزارش از دست نمی‌رود |
| Expo Push | خطا ثبت می‌شود؛ تغییر وضعیت انجام می‌شود |
| مدل NLP خراب/ناسازگار | گزارش ذخیره می‌شود؛ تحلیل رد می‌شود |
