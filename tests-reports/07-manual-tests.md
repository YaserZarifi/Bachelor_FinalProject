# چک‌لیست آزمون دستی

آنچه آزمون خودکار پوشش نمی‌دهد — سخت‌افزار واقعی، مجوزهای مرورگر/سیستم‌عامل،
رندر نقشه و ارزیابی بصری رابط کاربری — از این مسیر راستی‌آزمایی می‌شود.

**پیش‌نیاز:** `docker compose up --build`
سپس: شهروند `http://localhost:3001` · مدیر `http://localhost:3002` · API
`http://localhost:8080`

برای ورود به داشبورد مدیر ابتدا یک کاربر کارمند بسازید:

```bash
docker compose exec backend python manage.py createsuperuser
```

برای پر کردن نقشه و نمودارها با دادهٔ واقع‌نما:

```bash
docker compose exec backend python manage.py seed_reports --count 80
```

## ه) ثبت نتیجه

برای هر مورد ناموفق، این اطلاعات ثبت شود:

* شمارهٔ سناریو و کلاینت
* گام‌های دقیق بازتولید
* رفتار مشاهده‌شده در برابر رفتار مورد انتظار
* تصویر صفحه یا ویدئو
* خروجی کنسول مرورگر یا `docker compose logs backend`

سپس، اگر نقص در لایهٔ منطق باشد، **ابتدا یک آزمون خودکار** که آن را بازتولید
می‌کند نوشته شود و بعد اصلاح انجام گیرد؛ این‌گونه نقص دیگر بازنمی‌گردد.
